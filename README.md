# spring-first-devops

A small **Spring Boot + PostgreSQL** REST service used as a hands-on playground for learning DevOps tooling: **Docker**, **Docker Compose**, **GitHub Actions CI**, and **Kubernetes (Minikube)**.

The application itself is intentionally minimal — a single `Location` resource — so the focus stays on building, containerizing, and shipping it.

## Tech stack

| Layer | Technology |
|-------|-----------|
| Language | Java 21 |
| Framework | Spring Boot 3.5 (Web, Data JPA) |
| Database | PostgreSQL 16 |
| Build | Maven (wrapper included) |
| Containers | Docker, Docker Compose |
| CI | GitHub Actions → Docker Hub (`sarwarxsami/dunno`) |
| Orchestration | Kubernetes manifests (tested with Minikube) |

## API

Base path: `/locations`

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET`  | `/locations/getAll` | List all locations |
| `GET`  | `/locations/create` | Create a location named `"New Location"` (quick test endpoint) |
| `POST` | `/locations/create?name=<name>` | Create a location with the given name |

## Running

### With Docker Compose (recommended)

```bash
docker-compose up --build
```

- App: <http://localhost:8080>
- PostgreSQL: `localhost:5433` (mapped from container port 5432), database `testdb`, user/password `postgres`/`postgres`
- `init-db/init.sql` is mounted into `/docker-entrypoint-initdb.d/`, so it runs once on the database's first initialization.

Try it:

```bash
curl -X POST "http://localhost:8080/locations/create?name=Dhaka"
curl http://localhost:8080/locations/getAll
```

### Locally (without Docker)

Start PostgreSQL on `localhost:5432` with a `testdb` database, then:

```bash
./mvnw spring-boot:run
```

### On Kubernetes (Minikube)

```bash
minikube start
kubectl apply -f k8s/kubernetes.yaml
kubectl apply -f k8s/service.yaml
minikube service dunno-service
```

## CI/CD

`.github/workflows/ci.yml` runs on pushes and pull requests to `main`:

1. Checks out the code and sets up JDK 21 (Temurin)
2. Builds the JAR with `./mvnw clean package -DskipTests`
3. Builds the Docker image `sarwarxsami/dunno:latest`
4. On `main` only: logs in to Docker Hub (`DOCKER_USERNAME` / `DOCKER_PASSWORD` secrets) and pushes the image

## Known limitations

- The Kubernetes manifests use container port `3000` and probe `/readyz` / `/healthz`, while the Spring Boot app listens on `8080` and does not expose those endpoints yet. The manifests also don't provide a database or `SPRING_DATASOURCE_*` environment variables.
- `init.sql` defines `locations.id` as a plain `INTEGER PRIMARY KEY`, while the JPA entity uses `GenerationType.IDENTITY`; the column needs to be `SERIAL`/`IDENTITY` for inserts to succeed against the init-created table.
- Database credentials are hard-coded for local development.
